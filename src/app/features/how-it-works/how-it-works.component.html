♿ How it works

Accessibility QA,
automated end-to-end

A11yFix orchestrates the full WCAG 2.2 remediation lifecycle — from detecting violations to applying fixes — with an AI agent and a mandatory human approval gate.

Start an audit

The 7-step workflow

  1. 1

    🔍 Detect

    Submit any public URL. The backend runs axe-core via a headless Playwright browser and returns every WCAG 2.2 violation with its exact DOM selector and HTML snippet.

  2. 2

    📋 Understand

    Each finding is mapped to its WCAG 2.2 Success Criterion (e.g. 1.4.3 Contrast Minimum) with conformance level (A / AA / AAA). Interactive widgets are automatically matched to their WAI-ARIA APG pattern (Dialog, Tabs, Combobox…).

  3. 3

    💡 Propose

    Click "Propose AI Fix". A11yFix generates a contextual HTML diff — using the real DOM snippet from the audit — showing exactly what attribute, role, or style needs to change to be compliant.

  4. 🔒

    ✅ Approve Human required

    A human engineer reviews the before/after diff and clicks "Approve". This is a mandatory gate — no AI agent can bypass it. Without approval, the apply step is locked at the application state level.

  5. 5

    🛠️ Fix

    After approval, "Apply Fix" executes the apply_remediation WebMCP tool. The fix is applied to the live document and reflected in the application state.

  6. 6

    🔁 Verify

    A11yFix re-scans the element after the fix to confirm the violation is resolved and the WCAG criterion is now met.

  7. 7

    🧪 Prevent Regression

    A Playwright regression test is auto-generated for every applied fix. Add it to your CI pipeline to ensure the violation never reappears.

Who can use A11yFix?

WebMCP is one channel — not the only one. The same audit engine is accessible through three interfaces.

🧑‍💼

Non-developer

Designer · PM · QA Analyst

Uses the web UI directly. No setup required. Submit a URL, browse findings with plain-language severity badges, review the AI diff, and approve fixes — all through the visual interface.

Web UI only
👩‍💻

Developer

Accessibility engineer · Frontend dev

Uses both the web UI and the WebMCP Console — invoking tools directly, inspecting WAI-ARIA pattern specs, and reading structured JSON telemetry from every tool execution.

UI + WebMCP Console
🤖

AI Agent

Claude · Gemini · Copilot

The browser calls document.modelContext automatically. The agent reads findings, proposes remediations, and triggers fixes — always stopping at the human approval barrier before any write operation.

Visual Violations & Icon Legend

Understand every category of accessibility violations, severity indicators, and WAI-ARIA pattern markers evaluated by A11yFix.

🔴

Critical & Serious Errors

Severe barriers preventing assistive technology or low-vision users from consuming content.

  • Color Contrast (Very low contrast) SC 1.4.3 · Level AA / AAA

    Text contrast ratio is below the required 4.5:1 (normal text) or 3:1 (large text) threshold.

  • Label ✕
    Missing Form Label / Name SC 4.1.2 · Level A

    Input or button lacks an accessible name via <label>, aria-label, or aria-labelledby.

  • IMG ✕
    Missing Image Alternative Text SC 1.1.1 · Level A

    Informative <img> elements without an alt attribute or decorative empty alt="".

⚠️

Alerts & Usability Warnings

Potential accessibility degradation or suboptimal patterns that should be verified and polished.

  • TT ⚠️
    Very Small Text SC 1.4.4 · Level AA

    Font size is under 12px or hard to read on mobile screens without zooming.

  • 📋 ⚠️
    Redundant Title Text Best Practice

    The title attribute exactly duplicates the link or button text, causing screen readers to speak twice.

  • 👆 24px
    Touch Target Minimum Size SC 2.5.8 · Level AA (WCAG 2.2)

    Interactive touch target bounding box is under 24×24 CSS pixels with insufficient spacing.
